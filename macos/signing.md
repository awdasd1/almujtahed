# توقيع تطبيق الماك وتوثيقه (Developer ID + Notarization)

قرار مؤجل التنفيذ بطلب صاحب المشروع (نُسجل هنا بتاريخ ١٤٤٨/… الموافق ٩ نوفمبر ٢٠٢٦م، ونعود إليه عند اكتمال التطبيق). الهدف: أن يفتح «المجتهد» عند كل منزّل بلا تحذير «مطوّر غير معروف» من Gatekeeper.

## الطريق المعتمد — ولماذا ليس متجر آبل

- التوزيع يبقى مباشرًا من قنواتنا كما هو الآن؛ نوقّع بشهادة **Developer ID Application** ونوثّق عند آبل (فحص آلي ضد الفيروسات، بلا مراجعة بشرية، بلا عمولة).
- **متجر App Store مرفوض**: الحبس الرملي (Sandbox) إلزامي فيه، وتطبيقنا يقرأ ملفات الشاملة في مجلد تطبيق آخر ويشغّل خادم بايثون وجسور جافا وقاعدة متجهات عملياتٍ مستقلة — وهو ما لا يحتمله الحبس.

## حالة الاشتراك

- اشتراك Apple Developer Program مدفوع (٩٩$/سنة) وفعّال عند صاحب المشروع. يكفي وحده؛ لا شراء إضافي.

## ما جُهّز في الكود (تم، بانتظار الشهادة)

- `macos/build_app.sh`: مرحلة توقيع وتوثيق آلية بعد البناء:
  - تكتشف شهادة «Developer ID Application» في سلسلة المفاتيح (أو `ALMUJTAHED_SIGN_ID`).
  - توقّع المُشغّل ثم الحزمة بـ `--options runtime --timestamp` مع `macos/entitlements.plist`، وتتحقق بـ `codesign --verify --strict`.
  - إن وُجد ملف اعتماد توثيق باسم `almujtahed-notary` (أو `ALMUJTAHED_NOTARY_PROFILE`): تضغط الحزمة بـ `ditto`، وترفعها بـ `notarytool submit --wait`، ثم `stapler staple` و`stapler validate` و`spctl --assess`.
  - بلا شهادة: تُبنى النسخة غير موقعة كما كان سابقًا مع تنبيه مطبوع. وتعطيل التوثيق وحده: `ALMUJTAHED_NOTARIZE=off`.
- بنية الحزمة بسيطة ومؤاتية: ثنائي المُشغّل فقط (لا أطر خارجية داخلها)، والبقية نصوص وخطوط. حجمها ~٥٨MB فرفع التوثيق سريع.
- ملحوظة مطمئنة: عمليات بايثون تُبنى بيئتها في مجلد تشغيل المستخدم خارج الحزمة، وتوقيع الحزمة لا يقيّدها؛ المُشغّل لا يربط إلا أطر نظام آبل فلا حاجة لتصاريح استثنائية.

## خطوتان يدويتان متبقيتان على صاحب الحساب

### ١) إنشاء الشهادة

في **Xcode**: الإعدادات (⌘,) ← Accounts ← اختيار الفريق ← **Manage Certificates** ← زر **+** ← **Developer ID Application**.

- معرفة Team ID: بوابة المطوّر ← Membership، أو من الشهادة نفسها بعد إنشائها:
  `security find-identity -v -p codesigning` (تظهر بصيغة `Developer ID Application: الاسم (TEAMID)`).

### ٢) اعتماد التوثيق

1. من appleid.apple.com ← Sign-In and Security ← App-Specific Passwords: إنشاء كلمة باسم `almujtahed-notary` (تظهر مرة واحدة).
2. في Terminal (الإدخال مخفي):

```bash
xcrun notarytool store-credentials "almujtahed-notary" --apple-id "بريد الحساب" --team-id "TEAMID" --password "xxxx-xxxx-xxxx-xxxx"
```

## بعد إتمامهما (عمل الوكيل)

1. بناء عادي `./macos/build_app.sh ...` — سيوقّع ويوثّق تلقائيًا.
2. التحقق: `codesign --verify --strict` و`xcrun stapler validate` و`spctl --assess --type execute` بنتيجة accepted / source=Notarized Developer ID.
3. شحن إصدار جديد بالإجراء المعتاد (سجل إصدارات + رفع رقم + بناء التطبيقين + مزامنة + دفع).
4. يفتح التطبيق بعدها عند جميع المنزّلين الجدد بلا تحذير؛ المنزّلون القدامى يحتاجون تنزيل النسخة الموقعة مرة واحدة.

## ويندوز (مؤجل، للعلم)

- الخيارات: Azure Trusted Signing (~١٠$/شهريًا، سحابي، الأفضل إن شمل التحققُ بلدَنا وكيانَنا)، وإلا شهادة OV من Sectigo/DigiCert (~٢٠٠–٤٠٠$/سنة، مفتاحها على قطعة USB منذ ٢٠٢٣ — والتوقيع من جهاز بناء ماك أعسر معها، فيفضّل الحل السحابي).
- التوقيع يظهر اسم الناشر ويقلّل تحذيرات SmartScreen تدريجيًا مع تراكم السمعة؛ شهادات آبل وحدها لا تغطي ويندوز والعكس.
