# 🌟 منظومة المجتهد الشاملة والمستقلة (Al-Mujtahed Standalone Platform)

> **المكتبة الشاملة المضمنة والمكممة - بحث دلالي عميق، استوديو مشاريع، قارئ شاملة، ووكلاء مساعدون**  
> نسخة محمولة ذاتياً (Self-Contained & Fully Portable) مهيأة للنقل والتشغيل على أي جهاز أو سيرفر جديد بنسبة **100% دون أي فقد في البيانات أو النماذج**.

## قبل أي تعديل

بعد هذا الملف اقرأ [`dev.md`](dev.md). فيه بنية التطبيق، ومالك كل جزء، وحدود التعديل. أي منصة تعمل بالذكاء الاصطناعي — Cursor أو VS Code أو Lovable أو Antigravity أو منصة محلية أو سحابية — تكمل من هناك قبل تغيير الكود، ثم تراجع أعلى [`changes.md`](changes.md) لآخر سلوك شُحن.

## تشغيل نسخة المستودع على الجهاز المحلي

هذا المسار لماك وويندوز ولينكس بعد تنزيل المستودع أو سحبه بـ git. الملفات الضخمة ليست داخل المستودع. أمر واحد ينشئ بيئة بايثون، ويسحب محرك Qdrant ونموذج التضمين وسنابشوت المتجهات ونصوص الشاملة من Hugging Face إلى مواضعها داخل المجلد، ثم يفتح الواجهة.

يلزم Python 3.10 أو أحدث، وgit، ونحو 200 غيغابايت فارغة. السحب الأول طويل لأن سنابشوت المتجهات نحو 172 غيغابايت ونصوص الشاملة نحو 19 غيغابايت ونموذج التضمين نحو 4.4 غيغابايت. ما هو موجود لا يُعاد تنزيله.

على ماك أو لينكس، من داخل مجلد المشروع:

```bash
./start_local.sh
```

على ويندوز، من موجه الأوامر داخل المجلد نفسه:

```bat
start_local.bat
```

على ماك يمكن بناء تطبيق يُفتح بالنقر:

```bash
./macos/build_app.sh
```

يُنشئ `~/Downloads/المجتهد.app`. أول فتح يعرض نافذة التجهيز، ويسحب النماذج والسنابشوت إلى `~/Library/Application Support/Al-Mujtahed`، ثم يفتح الواجهة في المتصفح. إغلاق النافذة يوقف التطبيق.

بعد الإقلاع:

- الواجهة: `http://localhost:8085`
- لوحة المتجهات: `http://localhost:6333/dashboard`

السنابشوت ونصوص الشاملة يكتملان في الخلفية في أول تشغيل، والسجل في `web_ui/init.log`. شريط التقدم يظهر في نافذة صحة الخادم. أوقف الواجهة بـ Ctrl+C. Qdrant يبقى يعمل حتى يُغلق من النظام.

إن رغبت بتسريع السحب أو كان المستودع يطلب إذناً، انسخ `.env.example` إلى `.env` وضع التوكن في `HF_TOKEN` قبل الأمر. الأمر نفسه ينشئ `.env` إن لم يكن موجوداً ويضبط مضيف Qdrant على `127.0.0.1`.

تشغيل Coolify عبر Docker لم يتغير: الحاوية ما زالت تبدأ من `entrypoint.sh` وتسحب البيانات إلى القرص الثابت `/data`.

## 🚚 طريقة نقل المنظومة إلى جهاز جديد بنسبة 100%

### الخطوة 1: نسخ المجلد إلى الجهاز الجديد
قم بنسخ مجلد `almujtahed` بالكامل عبر قرص تخزين خارجي (External SSD) أو عبر الشبكة:
```bash
# على سبيل المثال، نسخ المجلد كاملاً إلى مسارك المفضل في الجهاز الجديد
cp -R /path/to/almujtahed /home/username/almujtahed
```

---

### الخطوة 2: تثبيت بيئة بايثون والاعتماديات
في الجهاز الجديد، افتح الطرفية (Terminal) داخل مجلد `almujtahed` وشغل:
```bash
cd almujtahed

# يُفضل إنشاء بيئة وهمية معزولة
python3 -m venv .venv
source .venv/bin/activate

# تثبيت متطلبات التشغيل
pip install -r requirements.txt
```

> **ملاحظة لنماذج GGUF على ماك (Metal) أو لينكس (CUDA):**
> لتفعيل تسريع المعالج الرسومي (Metal على Mac Apple Silicon):
> ```bash
> CMAKE_ARGS="-DGGML_METAL=on" pip install --upgrade --force-reinstall llama-cpp-python
> ```
> أو على سيرفرات لينكس ذات كروت Nvidia (CUDA):
> ```bash
> CMAKE_ARGS="-DGGML_CUDA=on" pip install --upgrade --force-reinstall llama-cpp-python
> ```

---

### الخطوة 3: تشغيل المنظومة

إذا كانت النماذج والسنابشوت موجودة مع النسخة المنسوخة:

```bash
./start_almujtahed.sh
```

إذا كانت النسخة من المستودع بلا هذه الملفات، استخدم `./start_local.sh` أو `start_local.bat` كما في قسم التشغيل المحلي أعلاه.

يقوم هذا السكربت تلقائياً بالآتي:
1. فحص بيئة بايثون وتوافر الحزم.
2. تشغيل خدمة مخزن المتجهات **Qdrant** على المنفذ `6333` بالبيانات الحية المفهرسة مسبقاً (8.15 مليون مقطع).
3. إطلاق خادم الويب **FastAPI** على المنفذ `8085`.
4. فتح المنظومة في المتصفح عبر الرابط:
   - **الواجهة الرئيسية**: `http://localhost:8085`
   - **لوحة تحكم المتجهات Qdrant**: `http://localhost:6333/dashboard`

## 🐳 خيار بديل: تشغيل Qdrant عبر دوكر (Docker)
إذا كنت تنتقل إلى نظام تشغيل مختلف (مثل Ubuntu Linux) وترغب في تشغيل Qdrant عبر Docker مع استخدام نفس مجلد البيانات المنسوخ دون إعادة فهرسة:
```bash
cd almujtahed/qdrant_service
docker run -d -p 6333:6333 -p 6334:6334 \
  -v "$(pwd)/storage:/qdrant/storage" \
  qdrant/qdrant
```
ثم شغل خادم التطبيق مباشرة:
```bash
cd ../web_ui
python3 server.py
```

## شروط الرفع إلى المستودع

نسخ المجلد إلى جهاز جديد ينقل البيانات والنماذج معه. الرفع إلى GitHub ينقل الكود فقط، ويبقى ما يلي على الجهاز أو على قرص الخادم:

- النماذج المحلية في `models/local`، وكل ملفات `*.gguf` وملفات السحب غير المكتملة `*.partial`.
- نموذج التضمين، ومجلد `models`، و`inference_models`.
- مخزن Qdrant ولقطاته والملف التنفيذي للمحرك.
- نصوص الشاملة في `shamela4_data`.
- الأسرار: `.env` ومفاتيح المزودين.
- حسابات الأعضاء والدعوات في `web_ui/members.json`، ورسائل المشرف في `web_ui/notices.json`.
- ذاكرة التطبيق `web_ui/app_memory.db`، وتفضيل الكرت `web_ui/gpu_mode.json`، والنسخ الاحتياطية، ومرفوعات المستخدمين.

قبل كل رفع تُراجع الملفات المتتبعة وتُفرَّغ من مشاريع البحث الشخصية ومجموعات الوكلاء الخاصة، فتبقى `web_ui/projects_data.json` و`web_ui/agent_groups_data.json` في المستودع بلا بيانات الباحث. هذه البيانات تبقى على الجهاز ولا تُحذف منه عند الرفع.

الدفع إلى `main` يكون دفعاً عادياً. إذا ظهر ملف من القائمة أعلاه ضمن التغييرات، يُخرج من الإيداع قبل الدفع.
